# MVP 범위 명확화 질문 (Clarification)

요구사항을 승인하시면서 **"핵심 기능 우선 MVP, 비기능 요구는 중요도 낮음"** 지시를 주셨습니다. 이 지시는 대부분 그대로 반영할 수 있으나, 한 가지 충돌 소지가 있어 확정이 필요합니다. (question-format-guide: 모순·모호성 발견 시 clarification 파일 생성)

## 감지된 충돌
- 방금 **Q1=A** 로 Security 확장을 **Full/blocking** 으로 켰습니다.
- 잠긴 제약 **C-SCOPE-1**: 우선순위는 `보호 경계 유지 → 데이터 비노출·정책 무결성 → 실제 기능 완성 → 재현성·사용성 → 성능 최적화 → 확장`. **"성능을 맞추려고 검사 전 전송·TLS 검증 해제·검증 실패 허용을 도입하지 않는다."**
- **C-AIDLC-2**: "단일 사용자 시제품 범위를 이유로 P0를 완화하지 않는다."

## 핵심 구분: AEGIS의 NFR은 두 종류입니다

AEGIS는 **보안 자체가 핵심 기능**인 제품입니다. 그래서 NFR 중 일부는 "부가 품질"이 아니라 **기능의 본질**입니다.

| 구분 | 해당 NFR | MVP에서 |
|---|---|---|
| **① 보안 집행형 NFR = 핵심 기능의 일부** | NFR-3(정책 무결성), NFR-4(데이터 비노출), NFR-5(TLS), NFR-8(fail-closed), NFR-9(감사 일관성), NFR-10(탐지 정확도) | 이것을 빼면 "격리·차단·검증"이라는 **기능 자체가 성립 안 함**. → MVP에 포함되어야 함 |
| **② 성능·최적화·사용성 NFR = 지금 미룰 수 있음** | NFR-1(RBI 지연 목표), NFR-2(프록시 지연 목표), NFR-7(60초 기동 최적화), NFR-12(사용성 세부), 집계 지표, RBI 화질, 모든 P1/P2 | MVP 이후 목표치로 튜닝. MVP에서는 "동작"만 확인하고 수치 목표는 후순위 |
