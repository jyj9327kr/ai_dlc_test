# AEGIS 요구사항

버전: 4.0 | 작성일: 2026-09-07 | 상태: 개발 착수용 기준안, 사람의 단계 승인 전

이 문서는 AI-DLC로 AEGIS를 개발할 때 사용할 제품 요구사항이다. 기존 요구사항과 검증 질문을 통합하고, 충돌하는 동작과 구현 범위를 정리했다. 기술·보안·개발 절차의 강제 조건은 같은 디렉토리의 [constraints.md](constraints.md)를 함께 적용한다. 아래 기본값은 이번 기준안의 결정이며, 과거 사람의 답변이나 승인으로 간주하지 않는다.

## 1. 의도와 해결할 문제

### 1.1 Intent Analysis

| 항목 | 정의 |
|---|---|
| 제품 의도 요약 | 개발자가 외부 웹을 확인하고, 로컬 AI 에이전트를 실행하며, 클라우드 LLM에 요청하는 과정에서 세 신뢰 경계를 통제하는 보안 워크스페이스를 만든다. 사용자 원문 인용이 아닌 제품 의도 요약이다. |
| 요청 유형 | New Project. 현재 제공된 작업 공간에는 기준 문서와 AI-DLC 규칙이 있으며 애플리케이션 구현은 없다. |
| 범위 | Cross-system. Chrome 확장, 격리 브라우저, 에이전트 실행 게이트, LLM 전송 프록시, 공통 정책·감사 모듈. |
| 복잡도·분석 깊이 | Complex / Comprehensive. 여러 실행 환경의 보안 경계를 다루므로 정상·거부·장애 경로와 추적 가능한 수용 기준을 모두 정의한다. |

### 1.2 문제와 제품 가치

| 문제 ID | 사용자의 상황과 손실 | 제품이 보장할 결과 | 성공 증거 |
|---|---|---|---|
| P-1 | 출처가 불명확한 링크의 내용을 확인해야 하지만 외부 페이지의 스크립트를 로컬 브라우저에서 실행하고 싶지 않다. | 보호 프로필에서 격리 대상 웹은 서버 브라우저가 실행하고 로컬에는 픽셀과 제한된 제어 메시지만 전달한다. | D-1: 원격 렌더링, 로컬 직접 요청 부재, 위험 액션 경고, 장애 시 차단. |
| P-2 | 에이전트가 사용하는 샌드박스 정책이 바뀌면 의도한 파일·네트워크 제한이 약화될 수 있다. | 승인된 서명 정책만 실행 게이트가 수용하며, 실제 자원 접근 제한은 OpenShell이 집행한다. | D-2: 정상 정책 실행, 한 바이트 변조 정책 거부, 허용 작업 성공·금지 자원 접근 실패. |
| P-3 | 프롬프트·코드·설정에 섞인 API 키가 LLM 제공자에게 전달될 수 있다. | 보호된 클라이언트의 지원 요청을 전송 전에 검사하고, 시크릿이 있으면 전체 요청을 차단한다. | D-3: 차단 요청의 업스트림 수신 0건, 정상 요청 수신 1건. |
| P-4 | 여러 보안 도구가 다른 정책·로그를 사용하면 어떤 경계에서 무엇을 막았는지 확인하기 어렵다. | 공통 정책 식별자와 작업 식별자로 세 방어 결과를 한 화면에서 확인한다. | D-1~D-3 이벤트를 같은 workflow_id로 조회하고 각 판정 사유를 확인. |

차별화의 중심은 개발자의 연속된 작업을 세 경계에서 보호하고 동일한 정책 버전·감사 기록으로 연결하는 데 있다. RBI, 샌드박스, 시크릿 탐지, ML-DSA 자체를 새로 발명했다고 주장하지 않는다. 정책 서명에 비대칭 키를 쓰는 직접적인 이점은 실행·검증 환경에 서명 비밀키를 배포하지 않는 것이다. 정책 서명만으로 정책 내용의 안전성이나 전체 통신의 양자내성이 보장되지는 않는다.

## 2. 사용자, 보호 범위와 용어

### 2.1 사용자

- 주 사용자: 외부 자료를 읽고 AI 코딩 도구를 사용하는 개발자. 보안 전문가가 아니어도 차단 이유와 다음 행동을 이해할 수 있어야 한다.
- 정책 관리자: 같은 장비를 관리하는 개발자 또는 팀 담당자. 설정 파일을 수정하고 서명·키 교체·실행 환경 준비를 수행한다. 별도 계정·RBAC 제품은 만들지 않는다.
- 검증 사용자: README만 보고 환경을 시작하고 정상·공격·장애 시나리오를 재현하는 동료. 숨은 수작업이나 실제 악성 사이트 없이 검증할 수 있어야 한다.

### 2.2 보호 범위

1. **웹 보호**: AEGIS 확장이 활성화된 전용 Chrome 프로필의 HTTP(S) 최상위 탐색. 명시한 신뢰 origin 외의 웹은 기본 격리한다. 원격 페이지의 하위 리소스와 새 창도 원격에서 처리한다.
2. **에이전트 보호**: `aegis-cage run`으로 시작한 OpenShell 샌드박스. 임의의 호스트 프로세스나 다른 실행기로 시작한 에이전트를 보호한다고 표시하지 않는다.
3. **LLM 전송 보호**: 프록시 경유와 직접 외부 연결 차단이 모두 적용된 보호 클라이언트. Anthropic Messages와 OpenAI Responses/Chat Completions의 텍스트 JSON 요청을 지원한다. OAuth 기반 웹 로그인, 모든 Claude Code/Codex 버전과 모든 전송 방식을 자동 지원한다고 주장하지 않는다.
4. **운영 단위**: 장비 1대, 로컬 사용자 1명, 동시에 격리 웹 세션 1개·에이전트 실행 1개·LLM 요청 1개를 기준으로 한다.
5. **신뢰 전제**: 호스트 관리자, 설치된 AEGIS 코드, 신뢰 공개키 저장소와 운영 설정은 신뢰한다. root 권한 공격자, 커널·브라우저 자체 취약점, 사용자의 확장 제거·보호 환경 이탈은 보장 범위 밖이다.

| 용어 | 의미 |
|---|---|
| 격리 | URL을 로컬에서 실행하지 않고 별도 서버 브라우저에서 실행·표시하는 것. 경고창이나 iframe만 띄우는 것은 격리가 아니다. |
| 차단 | 해당 자원 접근·프로세스 실행·외부 요청을 실제 집행 지점에서 거부하는 것. 화면에만 실패를 표시하는 것은 차단이 아니다. |
| fail-closed | 보호 대상 동작의 안전성 또는 필수 감사 기록을 확인할 수 없으면 그 동작을 허용하지 않는 것. 다른 독립 컴포넌트의 정상 작업까지 일괄 중단한다는 뜻은 아니다. |
| 시크릿 | 정의한 룰에 해당하는 자격증명 후보. 실제 유효성 확인을 위해 외부 인증 요청을 보내지 않는다. |
| 마스킹 | UI·오류·감사 기록에서 값 전체를 제거하는 것. 요청을 바꿔서 외부에 전송하는 redact 기능과 구분한다. |
| 보호 활성 | 필요한 정책 검증, 집행 지점, 감사 저장소의 준비 검사가 모두 통과한 상태. 단순히 프로세스가 떠 있는 상태가 아니다. |

## 3. 우선순위와 범위

**P0/Must**는 최초 제공 범위의 완료 조건이다. 모든 P0 수용 기준을 만족해야 완료로 표시한다. **P1/Should**는 P0 검증 후 추가하며 미구현이면 한계로 표시한다. **P2/Could**는 후속 확장이다. 안전한 차단을 경고·통과로 바꾸어 P0를 축소하지 않는다.

| 범위 | 포함 항목 |
|---|---|
| P0 | 실제 픽셀 격리와 위험 액션 통제, 실제 OpenShell 실행과 ML-DSA 검증, 지원 LLM 요청의 전송 전 차단, 공통 정책·로컬 감사 기록, 최소 상태 화면, 단일 기동 진입점, 재현 가능한 D-1~D-3 및 장애 테스트. |
| P1 | SHA-256 기반 탐지 예외 목록, 서명된 정책의 동적 갱신, gzip 텍스트 요청 지원, RBI 품질·지연 최적화, 집계 지표. 각각 §11의 추가 수용 기준을 적용한다. |
| P2 | 요청 자동 redact, 정책 편집 GUI, 감사 로그 해시체인·외부 서명 보관, WebRTC, 다중 세션·브라우저, ML-DSA-87, 자동 키 회전·HSM/KMS, 외부 위협 피드. |
| 제외 | 멀티테넌트 SaaS, 중앙 조직 관리·SSO, 모바일, 자동 클라우드 배포, EDR·악성코드 분석 엔진 개발, 임의 파일·이미지·음성 내 시크릿 탐지, 모든 CLI 투명 호환, 호스트 전체 트래픽 감시, 커널 방어, 생산 서비스 SLA·보안 인증 취득. |

격리 페이지의 다운로드·업로드·클립보드 전달·표준 비밀번호 필드(`type=password`) 입력은 P0에서 모두 차단한다. 안전한 파일 반출이나 실제 계정 로그인은 제공 범위에 포함하지 않는다. 기존 자료의 상충하는 ‘확인 후 다운로드 허용’ 규칙은 적용하지 않는다. 일반 텍스트 필드로 위장한 자격증명 수집을 모두 식별한다는 보장은 하지 않는다.

## 4. Units of Work와 사용자 여정

### 4.1 다섯 개 Unit

| Unit | 이름 | 책임·주요 입출력 | 의존 |
|---|---|---|---|
| U-1 | WebIsolate | URL 분류, Chrome 보호 탐색, 서버 브라우저 수명, 픽셀·입력 중계, 위험 액션 UI. | U-4 정책, U-5 이벤트 계약 |
| U-2 | AgentCage | 검증된 정책으로 OpenShell 실행, 워크스페이스·통신 경계 확인, 실행 결과 표시. | U-4 서명 검증, U-5 감사 |
| U-3 | SecretGuard | 지원 요청 정규화, 탐지, 업스트림 전송 또는 거부, 안전한 오류 응답. | U-4 탐지 정책, U-5 감사 |
| U-4 | PolicyCore | 버전 있는 공통 설정, ML-DSA 서명·검증, 공개키 신뢰목록, 검증된 정책 스냅샷. | 방어 Unit을 참조하지 않음 |
| U-5 | AuditTrail | 구조화 이벤트의 직렬 추가 기록, 조회, 최소 통합 상태 화면. 기존 AuditFabric의 역할을 이 이름으로 통일한다. | 공통 이벤트 타입만 사용 |

공통 데이터 타입은 별도 모듈에 둔다. 의존 방향은 `U-1/U-2/U-3 → U-4 및 U-5`이며 U-4와 U-5는 서로의 구현을 참조하지 않는다. 5 Unit은 개발·테스트 책임 경계이며 5개 독립 서비스 배포를 요구하지 않는다. 먼저 공유 계약과 U-4/U-5를 확립하고 `U-3 → U-2 → U-1` 순서로 통합한다. 사용자는 준비 검사 후 SecretGuard, AgentCage, WebIsolate 순으로 활성화할 수 있다.

| US-6 | 동료로서 README만으로 설치와 검증을 반복하고 싶다. | 사전 준비, 기동, 3 시나리오, 장애 복구, 정리 절차를 수행하고 결과 파일을 찾는다. | FR-0.1~FR-0.3, T-BOOT |

## 5. P0 기능 요구사항과 수용 기준

각 행은 필수 요구다. AC의 ‘전제 → 행동 → 결과’를 자동 테스트 또는 명시한 수동 재현으로 확인한다. 상세 기본값과 메시지 계약은 constraints.md를 따른다.

### 5.1 공통 실행 경험

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-0.1 | `scripts/aegis doctor`, `up`, `down`, `demo`, `test`를 하나의 실행 진입점으로 제공한다. | 의존성이 준비된 환경에서 `up` 1회로 로컬 제어 UI·프록시·감사 저장소·RBI 준비 상태가 표시된다. OpenShell 실행은 사용자의 `run` 요청 때 수행한다. 미준비 항목은 이름·복구 절차를 출력하고 성공 종료코드를 반환하지 않는다. |
| FR-0.2 | 각 컴포넌트를 준비 중·보호 활성·차단 상태·사용 안 함으로 구분한다. | 프록시·RBI·감사 저장소 하나를 중지하면 3초 이내 해당 카드가 활성 상태를 잃는다. 보호되지 않는 요청이나 비활성 Unit을 ‘보호됨’으로 표시하지 않는다. |
| FR-0.3 | 실행마다 workflow_id를 만들고 UI·CLI·시나리오 실행기에 전달한다. | D-1~D-3를 같은 작업으로 실행하면 동일 workflow_id와 서로 다른 event_id로 조회된다. 임의 다른 세션 ID만으로 이벤트나 격리 세션에 접근할 수 없다. |

### 5.2 U-1 WebIsolate

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-1.1 | 보호 프로필의 HTTP(S) 탐색을 정책에 따라 직접 허용·격리·차단으로 판정한다. | 명시한 신뢰 origin은 직접 열리고, 지정 위험 도메인과 미분류 외부 origin은 원격 격리된다. 최초 요청·주소창 입력·링크 클릭·새 탭·서버 리다이렉트에서 대상 페이지가 로컬에 먼저 실행되지 않는다. 정책 부재 시 직접 접속하지 않는다. |

### 5.4 U-3 SecretGuard

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-3.1 | 보호 클라이언트의 지원 LLM 요청을 프록시로 강제 경유시킨다. | AgentCage에서 실행한 보호 HTTP 클라이언트가 SecretGuard를 통해 정상 요청을 전송한다. 프록시 종료 후 같은 클라이언트의 요청과 프록시 설정을 제거한 직접 연결 시도는 모두 실패한다. 환경변수만 설정한 상태는 강제 경유 검증으로 인정하지 않는다. |
| FR-3.2 | 본문과 허용된 인증 필드를 제외한 사용자 제어 헤더를 검사한다. | JSON 문자열·배열·중첩 객체를 검사하고 escape를 해제한 문자열도 검사한다. §8.2의 시크릿 8개를 모두 검출한다. 정규식과 문맥 있는 엔트로피 탐지를 사용하며 LLM 판정 호출은 하지 않는다. |
| FR-3.3 | 탐지 시 요청 전체를 전송 전에 차단한다. | 403 응답에 `AEGIS_SECRET_BLOCKED`, event_id, rule_id, 안전한 위치 식별자를 포함한다. 업스트림 관측 서버에 요청 본문·헤더가 전달되지 않는다. 후속 정상 재시도는 새 요청으로 처리한다. |
| FR-3.4 | 정상 인증과 정상 콘텐츠는 손상 없이 전달한다. | 정확한 제공자 host의 규정된 인증 헤더는 전송용 자격증명으로 처리하고 로깅하지 않는다. 동일 키가 본문이나 다른 헤더에 있으면 차단한다. 허용한 JSON의 본문 bytes와 제공자 응답·SSE의 의미를 변경하지 않는다. |
| FR-3.5 | 검사하지 못한 요청은 명시적으로 거부한다. | 크기 초과는 413, 미지원 본문·압축은 415, 잘못된 JSON은 400, 내부 검사·감사 장애는 503으로 거부한다. chunked 요청도 상한 내에서 끝까지 수신·검사 후 전달한다. 초과·시간 초과를 경고 후 통과로 바꾸지 않는다. |
| FR-3.6 | TLS 복호화·전송 대상을 지원 제공자로 한정한다. | 정확한 host·port·path·method만 수용하고 다른 목적지의 CONNECT·요청은 거부한다. 업스트림 인증서 검증을 끄지 않는다. 로컬 CA 신뢰는 보호 클라이언트에만 설정한다. |

## 6. 사용자 인터페이스 동작

UI는 한글을 기본으로 하며 Unit 이름·rule_id·event_id는 영문 식별자를 유지한다. 대시보드는 상태 카드 3개, 공통 정책 요약, 최근 이벤트 목록·상세, 시나리오 실행 안내만 제공한다. 별도의 복잡한 관리 콘솔을 만들지 않는다.

| 상황 | 반드시 보여줄 정보 | 사용자의 다음 행동 |
|---|---|---|
| 최초 준비 | 필요한 의존성, CA 신뢰 설정 범위, 확장 설치 여부, 각 상태 검사 결과 | 안내된 준비 작업 후 다시 검사 |
| 웹 격리 활성 | ‘격리됨’ 텍스트, 목적지 host, 픽셀 화면, 종료 버튼 | 페이지 읽기·스크롤·허용된 클릭 |
| 위험 액션 차단 | 무엇을 막았는지, 사유, event_id. 색상만으로 전달하지 않음 | 계속 읽기 또는 세션 닫기 |
| 정책 검증 실패 | `POLICY_SIGNATURE_INVALID` 등 구체적 코드, 실행되지 않았다는 설명 | 관리자에게 검증된 정책 재발급 요청 |
| 시크릿 차단 | 룰 이름·배열 인덱스 등 안전한 위치, 전체 값은 `[REDACTED]`, 업스트림 미전송 | 입력에서 해당 값을 제거하고 다시 요청 |
| 보호 기능 장애 | 영향받는 보호와 실패 이유, 재시도 가능 여부 | 컴포넌트 복구 후 새 작업 시작 |

키보드 Tab으로 버튼·필터에 접근하고, 포커스가 보이며, 경고는 텍스트와 접근 가능한 알림 영역으로 전달한다. 목적지·오류 메시지를 HTML로 해석하지 않는다. 보호 예외나 비밀값 보기 버튼은 P0에 없다. 한 화면의 상태와 실제 집행 결과가 충돌하면 보호 활성 표시를 내린다.

| NFR-1 | P0 | RBI 조작 가능성 | 1280×720·10fps 설정에서 입력→화면 반영 P95 ≤ 300ms, 준비된 서버의 첫 프레임 ≤ 5초. <150ms와 1080p/15fps는 P1 최적화 목표. |

## 8. 검증 시나리오와 시험 데이터

### 8.1 세 가지 종단 시나리오

시나리오는 자체 호스팅한 무해한 시험 페이지·임시 프로젝트·제공자 호환 수신 fixture를 사용한다. 실제 피싱 사이트·악성코드·유효한 타인 키는 사용하지 않는다. fixture는 외부 입력과 수신 관측에만 사용하며 AEGIS 판정·ML-DSA·OpenShell·원격 브라우저를 mock으로 대체하지 않는다.

| ID | 준비·행동 | 합격 기준·저장할 근거 |
|---|---|---|
| D-1 웹 격리 | 시험 페이지에 버튼·스크롤·무해한 JS 표식·mailto·다운로드·비밀번호 필드를 둔다. 보호 프로필에서 링크를 열고 버튼, 메일 링크, 다운로드를 시도한다. RBI를 중단한 뒤 다시 연다. | 원격 브라우저에서 표식이 실행되고 로컬에는 픽셀만 표시된다. Chrome 네트워크 기록에 대상 직접 요청 0건, 허용 입력 반영, 메일 앱 실행·파일 반출 0건, 장애 시 차단. 격리 화면과 안전한 이벤트·요청 출처 관측을 함께 저장한다. |
| D-2 정책·샌드박스 | 서명한 policy.yaml로 임시 프로젝트 파일을 수정하는 결정적 명령을 실행한다. 호스트 표식 파일 읽기와 비허용 네트워크 연결을 시도한다. 정책 한 바이트를 바꾼 복사본으로 재실행한다. | 정상 작업 성공, 금지 접근 실패, 변조 정책에서는 OpenShell 생성 호출 0회·명령 시작 0회. 실제 적용 digest·pubkey_id·안전한 종료 결과를 보관한다. LLM 호출 없이도 실행 게이트와 샌드박스 기능을 재현한다. |
| D-3 전송 보호 | 제공자 호환 fixture를 업스트림에 두고 API 키 형식의 시험값이 포함된 텍스트 JSON을 AgentCage 안의 보호 HTTP 클라이언트에서 전송한다. 키 제거 후 재시도하고 정상 SSE도 확인한다. 이어 프록시를 중단한다. | 시크릿 요청은 403·업스트림 수신 0건, 정상 요청은 수신 1건·응답 전달. U-2의 허용 네트워크가 U-3로만 연결됨을 확인하고 프록시 종료 후 직접 fallback이 없어야 한다. request_id별 수신 카운터, 차단 이벤트, 평문 미저장 검사 결과를 저장한다. |

모든 시나리오는 초기화 가능한 fixture와 한 개의 workflow_id로 묶는다. 재실행할 때 이전 실행의 이벤트·카운터와 섞이지 않아야 한다. 클라우드 추론을 사용한 실서비스 호환성 확인은 별도 결과로 기록하며 fixture 성공을 실제 제공자·특정 CLI 호환 검증으로 대체하지 않는다.

### 8.2 시크릿 탐지 고정 코퍼스

모든 키는 비활성 합성값이며 테스트 파일에 `SYNTHETIC / NEVER VALID`임을 명시한다. 코퍼스와 기대 결과를 탐지 구현 전에 고정하고, 통과를 위해 시험 문자열 자체를 탐지기에 하드코딩하지 않는다. 각 양성 입력은 기본 인증 헤더를 제외하면 하나의 탐지 원인만 갖는다.

| 양성 ID | 입력 유형 | 기대 |

### 9.3 Definition of Done

다음을 모두 충족해야 최초 제공 범위를 완료로 선언한다.

1. 모든 P0 FR·NFR을 구현하고 정상·거부·장애 검증 결과를 남긴다. 미수행·실패·미구현 항목을 통과로 표시하지 않는다.
2. README에 사전 조건, 기동, 확장·CA 범위, 세 시나리오, 오류 복구, 종료·정리, 지원 환경과 한계를 기록한다.
3. `.env.example`은 변수명·용도만 담고 비밀값은 제외한다. 버전 잠금, 시험 데이터, 공개키 예제와 새 키 생성 절차, 라이선스 표기를 제공한다.
4. AI-DLC 단계별 산출물·의사결정·실제 사람 승인·상태·검증 결과가 일치하고, 5 Unit의 책임과 요구사항 추적표를 유지한다. 절차 세부는 constraints.md §12를 따른다.
5. 제품 가치 설명에 기존 구성요소 재사용과 AEGIS가 구현한 통합 부분을 구분하고, 한계와 재현 가능한 근거를 제시한다.
6. 알려진 P1/P2 미구현 항목과 잔여 위험을 명시한다. 더 많은 기능을 만들었다는 이유로 실패한 P0를 완료 처리하지 않는다.

## 10. 결정 상태와 남은 검증

### 10.1 본 기준안의 기본 결정

기본 판정은 웹 미분류=격리, 위험 액션=차단, 시크릿=요청 차단이다. 정책은 ML-DSA-65로 서명하며 P0 갱신은 재시작 방식이다. 프록시는 지원 제공자 전용이고, 본문은 전체 검사 후 전달한다. UI는 최소 통합 화면이며 감사 로그는 로컬 추가 기록이다. 각 상세값은 constraints.md가 정의한다. 이 결정들을 선택지 없는 반복 질문으로 다시 묻지 않는다.

### 10.2 환경에 의해 확인해야 하는 항목

| ID | 확인할 항목 | 담당 단계·기본 처리 | 실패 시 처리 |
|---|---|---|---|
| V-1 | 실제 실행 호스트의 OpenShell·Landlock·컨테이너 지원과 격리 동작 | Inception에서 실행 가능성 확인, 성공 조합을 버전 고정. Linux VM을 기준 환경으로 사용. | 격리 없는 대체를 성공으로 처리하지 않고 지원 환경에서 다시 검증. |
| V-2 | liboqs와 Python 바인딩의 ML-DSA-65 실동작 | Inception에서 키 생성→서명→정상·변조 검증 smoke test. | 검증된 빌드·이미지 사용. 다른 알고리즘으로 자동 대체하지 않음. |
| V-3 | 보호 클라이언트와 프록시의 CA·라우팅·직접 egress 차단 | Application/Infrastructure Design에서 소규모 연결 검증 후 고정. | 개별 상용 CLI가 호환되지 않으면 지원 범위에서 제외·명시. P0는 AgentCage 안의 HTTP 시험 클라이언트로 실제 경유·차단을 검증하며, 이 경로까지 실패하면 P0 미완료. |
| V-4 | 브라우저 프로필과 RBI 사이 지연·Chrome 탐색 가로채기 | U-1 설계·구현 초기에 DNR과 픽셀 표시 검증. | 원격 집행은 유지하고 품질 조정. 미지원 탐색 경로를 몰래 직접 허용하지 않음. |

이 항목들은 제품 의도에 대한 미답변 질문이 아니라 구현 환경 검증 작업이다. 정확한 버전·포트 전달 세부처럼 실행으로 결정할 수 있는 값은 검증 결과로 잠그고, 제품 범위나 보안 보장이 달라지는 경우에만 변경 이유와 영향받는 AC를 검토한다.

## 11. P1 추가 수용 기준

| ID | 기능 | 추가 완료 기준 |
|---|---|---|
| EXT-1 | 탐지 예외 목록 | rule_id·제공자 host·값 digest·만료·사유에 한정한다. 해당 값 외 다른 시크릿은 계속 차단하며 예외 사용도 기록한다. 클릭 한 번으로 정책 전체를 우회하지 않는다. |
| EXT-2 | 서명 정책 동적 갱신 | AEGIS 갱신 경로에서 재검증·적용 완료 확인·감사를 수행한다. 실패한 새 정책이 활성화되지 않으며, 정적 정책 변경은 재생성한다. |
| EXT-3 | gzip 텍스트 JSON | 압축 크기·해제 크기·팽창률을 제한하고 해제 후 전체 검사한다. 압축 폭탄·비정상 압축은 업스트림 전송 없이 거부한다. |

| EXT-5 | 집계 지표 | PQC 검증 실패 수, 시크릿 차단 수, RBI 지연 초과 수를 이벤트와 일치하게 표시한다. 누락된 계측값을 0으로 표시하지 않는다. |

## 12. 알려진 한계와 후속 방향

정책 서명은 서명자가 허용한 정책의 출처와 bytes를 확인할 뿐 악의적인 정책 자체를 안전하게 만들지 않는다. 단일 장비의 신뢰 관리자 또는 서명 개인키가 손상되면 보호가 약화될 수 있다. 기존에 올바르게 서명된 정책의 롤백 방지는 P0에 없다.

픽셀 격리는 원격 페이지가 로컬에서 실행되는 것을 제한하지만 사용자가 원격 페이지에 직접 입력한 정보나 브라우저 엔진 취약점을 완전히 해결하지 않는다. 파일·클립보드·비밀번호 통로를 막아도 자유 텍스트 입력에 대한 DLP는 제공하지 않는다. 시크릿 탐지는 정해진 형식·문맥의 텍스트 후보에 한정되며 분할 인코딩, 사용자 정의 암호화, 이미지·파일 내 유출을 모두 탐지하지 않는다.

감사 파일은 애플리케이션 관점에서 추가만 수행하며 root에 대한 변경 방지 저장소는 아니다. 후속 제품화에서는 신뢰키 배포·폐기 자동화, 외부 감사 보관, 우회 내성 강화, 클라이언트 호환 범위와 실제 데이터 코퍼스 확장을 별도 검토한다.
